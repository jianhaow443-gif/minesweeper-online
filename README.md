# 扫雷 · 双人联机

一个可以直接在浏览器里玩的扫雷，支持**两个人一起扫同一块雷区**。纯静态页面，不需要后端，棋盘数据点对点直传。

在线玩：https://jianhaow443-gif.github.io/minesweeper-online/

## 玩法

**单人**：打开就能玩。左键翻开，右键插旗，数字上再点一次快速展开周围。最佳成绩按难度存在浏览器本地。

**双人联机**：
1. 一个人点右上角「联机」→「创建房间」，拿到 6 位房间码
2. 把房间码或邀请链接发给朋友
3. 对方点「联机」输入房间码（或直接打开链接）就能进

进去之后两个人看到的是**同一块雷区**：谁翻开的格子、谁插的旗、剩余雷数、计时、胜负全部实时同步。左下角会显示两个人各自翻开了多少格，还能看到对方的鼠标停在哪一格（绿色描边）。

## 难度

| 难度 | 尺寸 | 雷数 |
| --- | --- | --- |
| 初级 | 9 × 9 | 10 |
| 中级 | 16 × 16 | 40 |
| 高级 | 30 × 16 | 99 |

联机时任意一方点难度，两边一起换图。

## 技术实现

- 单文件 `index.html`，零构建、零依赖（`peerjs.min.js` 已内置在仓库里，不依赖 CDN）
- 房间配对和 NAT 穿透用 [PeerJS](https://peerjs.com/) 的公共信令服务 + WebRTC DataChannel
- 房主是权威端：所有点击都由房主结算，再把棋盘快照广播给客机，避免两端状态漂移
- 快照只传「哪些格翻开了 / 哪些插了旗 / 已翻开格子的数字」，未结束时不传雷的位置
- 用完即走，服务器不存任何东西（棋局只在两台设备之间传输）

### 关于连接

WebRTC 需要两端能协商出直连路径，绝大多数家庭网络没问题。如果卡在「正在连接房主」，通常是：

- 房间码打错了
- 房主那边已经把页面关了
- 双方都在严格的对称 NAT（部分公司网络 / 校园网）后面，且 STUN 打不通——这种情况需要自建 TURN 中继

## 本地跑

```bash
python -m http.server 8000
# 打开 http://localhost:8000
```

（直接双击 `index.html` 用 `file://` 打开也能单人玩，但联机建议走 http/localhost，部分浏览器会限制 `file://` 下的 WebRTC。）
